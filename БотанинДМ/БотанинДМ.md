# Практическая работа №103. Рефакторинг

## 1. Выбранный проект
- **Репозиторий (fork):** https://github.com/denbotanin-source/GildedRose-Refactoring-Kata
- **Оригинал:** https://github.com/emilybache/GildedRose-Refactoring-Kata
- **Описание:** Учебный проект GildedRose — имитация магазина с обновлением качества товаров. Код намеренно содержит «запахи» для практики рефакторинга.
- **Стек:** Java 17, Maven (mvnw), JUnit 5.

## 2. Использованные принципы рефакторинга
- Extract Method (Извлечение метода)
- Replace Magic Number/String with Constant (Замена «магических» значений константами)
- Устранение дублирования кода (DRY)
- Характеризующие тесты (characterization tests) как «страховка» перед рефакторингом

## 3. Описание выполненного рефакторинга

### Обнаруженные проблемы
- **Long Method:** `updateQuality()` ~70 строк, вложенность 4 уровня.
- **Duplicated Code:** проверки `quality < 50` — 7 раз, `quality > 0` — 3 раза, строковые литералы товаров — многократно.
- **Magic Numbers/Strings:** `50`, `0`, `11`, `6`, `"Aged Brie"`, `"Sulfuras..."` и т.п.

### Как решались
- Перед рефакторингом заглушка `foo()` заменена на 13 характеризующих тестов.
- Логика по типам товаров вынесена в отдельные приватные методы `updateItem`, `updateQualityBeforeExpiry`, `updateBackstagePassBeforeExpiry`, `updateQualityAfterExpiry`.
- Дубли проверок заменены на `increaseQuality` / `decreaseQuality`.
- Имена товаров вынесены в константы, добавлены предикаты `isAgedBrie` / `isBackstagePass` / `isSulfuras`.
- Магические числа заменены на `MAX_QUALITY = 50`, `MIN_QUALITY = 0`.

### Результат
- `updateQuality()` сократился до 3 строк.
- Все 13 тестов проходят до и после — поведение сохранено.
