# Лабораторная работа №103. Рефакторинг

## 1. Выбранный проект

**Название:** 103-refactoring-exercise

**Репозиторий:** https://github.com/SoftwareEngineering2026/103-refactoring-exercise

**Язык программирования:** Python 3.13

**Используемые технологии:** Python, стандартный модуль `csv`, Coverage.py, Git, GitHub.

**Описание проекта:**

Учебный проект для работы с данными о финансировании стартапов, хранящимися в CSV-файле.

Класс `FundingRaised` предоставляет два основных метода:
- `where()` для поиска записей по заданным условиям;
- `find_by()` для поиска первой подходящей записи.

## 2. Обнаруженные проблемы

При анализе файла `funding_raised.py` были выявлены следующие проблемы:

1. **Дублирование кода.** Преобразование строк CSV в словари повторялось в нескольких частях программы.
2. **Повторяющаяся логика чтения файла.** Методы `where()` и `find_by()` самостоятельно открывали и считывали один и тот же CSV-файл.
3. **Избыточные условные конструкции.** Для поиска по каждому полю использовались отдельные блоки условий и циклы.
4. **Сложность сопровождения.** При изменении структуры данных приходилось бы редактировать несколько одинаковых участков.

## 3. Применённые принципы рефакторинга

**DRY (Don't Repeat Yourself)**

Устранение повторяющихся участков кода и объединение общей логики в переиспользуемые методы.

**Extract Method (Выделение метода)**

Выделение отдельных методов для загрузки CSV и преобразования строк в словари.

**Simplify Conditional Logic (Упрощение условной логики)**

Замена повторяющихся условных конструкций универсальным механизмом фильтрации.

## 4. Выполненный рефакторинг

В файле `funding_raised.py` были выполнены следующие изменения:

1. Создан метод `_row_to_dict()`, преобразующий строку CSV в словарь.
2. Создан метод `_load_data()`, отвечающий за чтение CSV-файла.
3. Упрощён метод `where()`: вместо отдельных блоков фильтрации используется словарь соответствий полей и индексов столбцов.
4. Упрощён метод `find_by()`: устранены повторяющиеся блоки поиска и преобразования данных.
5. Сохранены существующие публичные методы и порядок обработки условий поиска.

В результате код стал компактнее, понятнее и удобнее для дальнейшего сопровождения.
