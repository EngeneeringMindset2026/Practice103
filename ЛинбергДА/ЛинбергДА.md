## Проект

Учебный проект [103-refactoring-exercise](https://github.com/SoftwareEngineering2026/103-refactoring-exercise), реализация на Python (`python/funding_raised.py`). Класс `FundingRaised` читает CSV с раундами инвестиций стартапов и ищет записи: `where()` возвращает все записи по фильтрам, `find_by()` первую подходящую.

Стек: Python 3, модуль `csv`, тесты на pytest.

## Принципы рефакторинга

- Перед изменениями поведение зафиксировано тестами (характеризационные тесты).
- Изменения маленькими шагами: после каждого шага все тесты проходят, каждый шаг в отдельном коммите.
- Повторяющийся код вынесен в одно место (DRY).
- Вместо номеров столбцов используются имена полей.
- Поведение кода не меняется, неочевидные места описаны комментарием.

## Найденные проблемы и решения

| Проблема | Решение |
|---|---|
| Блок чтения CSV скопирован в оба метода | метод `_read_rows()` |
| Преобразование строки в словарь (10 строк) скопировано 5 раз | список `FIELDS` и `_read_records()` через `dict(zip(...))` |
| 4 одинаковых фильтра в `where()` и 4 в `find_by()`, отличаются только индексом столбца | цикл по `FILTER_FIELDS` с обращением по имени поля |
| Неиспользуемая переменная `funding` | удалена |
| Путь `../startup_funding.csv` зависит от текущей папки: код работал только при запуске из `python/` | путь строится от расположения модуля (`CSV_PATH`) |
| Изменяемый аргумент по умолчанию `options = {}` | `options=None` |
| В репозитории лежит скомпилированный `funding_raised.pyc` | удалён, `*.pyc` в `.gitignore` |

Неочевидное поведение `find_by()` сохранено: условия не объединяются через «И», а проверяются по очереди (company_name, city, state, round), и возвращается первая найденная запись.

Объём `funding_raised.py`: 137 -> 49 строк.
